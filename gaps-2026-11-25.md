# SupplyChain engineering guideline gap analysis

The biggest gaps against [the engineering guidelines](guideline.md) are the **Java 8 runtime across all three services**, the **absence of automated test gates in the reviewed repositories**, and **code that hides failures or hardcodes credentials**. The existing REST/MySQL/RabbitMQ architecture can stay; the guideline does not require replacing RabbitMQ, JSP, or `RestTemplate`. See [research.md](research.md) for the current architecture and workflow.

| Area | Recommended change |
| --- | --- |
| **All three services: Java and build** | Move local builds, CI, and Docker build/runtime images to Java 21 and set Maven compiler `release` to `21`. Upgrade to a compatible Spring Boot release. Verify the frontend's JSP/WAR deployment on a compatible Tomcat, and handle the `javax` to `jakarta` changes for servlet, JPA, and validation APIs as applicable. |
| **Backend: validation, money, and secrets** | Validate order input at the API boundary, including required fields and a positive total. Replace `totalAmount.doubleValue()` with `BigDecimal.signum()` or `compareTo()`, and apply explicit rounding where money is calculated. Move MySQL and RabbitMQ credentials to approved secret storage. For `order.created`, make publication failure visible and recoverable; a transactional outbox is one option if an accepted order must reliably produce an event. |
| **Frontend: truthful errors and usable order flow** | Show an unavailable state when dashboard API calls fail instead of displaying zero counts. Map backend validation errors to user-safe field feedback and preserve form input. Populate the vendor dropdown from backend data instead of hardcoded IDs. Wire the pending page's nonfunctional **Approve** link to the backend operation, or remove it until approval is supported in the UI. |
| **Worker: recoverable failures and safe logs** | Move RabbitMQ credentials to approved secret storage. Keep listeners thin; replace full-payload logs with safe event identifiers and stop swallowing processing exceptions. Configure bounded retries and a dead-letter policy for failed messages. Keep simulated notifications clearly labeled so logs don't imply real delivery. |
| **All three services: coding standards and unit tests** | Replace field injection with constructor injection and enforce explicit imports and formatting. Add deterministic JUnit 5 tests for order validation and approval, frontend error handling, and worker failure paths. Enforce **at least 75% production line coverage from unit tests in each project** with JaCoCo; report integration and UI coverage separately. |
| **Frontend: browser tests** | Make Playwright or Selenium a required PR check. Cover dashboard loading, valid order submission and appearance in the pending list, validation feedback, and inventory browsing. Add approval coverage once the UI supports it. Use isolated data, stable selectors, condition-based waits, and screenshots or traces on failure. |

**Recommended order:** Remove and rotate any hardcoded credentials that were used in a deployed environment. Add focused regression tests before changing the runtime, then migrate to Java 21 and update the dependencies and container images. Fix the failure-handling and UI gaps, and make the unit-coverage and browser-test checks required before merging.
